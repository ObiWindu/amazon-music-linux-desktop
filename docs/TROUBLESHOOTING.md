# Troubleshooting

- Missing WebEngine bindings: install qt6-qtwebengine and python3-pyside6.
- Missing CDM: install widevine-installer; check /var/lib/widevine.
- Playback starts, then stops after ~1s: root cause confirmed with an instrumented live run using the 2022 ARM64 CDM (4.10.2662.3). Sequence: EME session created, `generateRequest` OK, license POST to `music.amazon.fr/ZAZ/api/dmls/` → HTTP 400 `ForbiddenException`, `denialReason: VMP_VALIDATION_FAILED` ("UNVERIFIED request not eligible for LD content"), then the page empties the media element and retries once. Amazon validates the Widevine Verified Media Path; the 2022 build fails that check. The app now discovers and prefers newer component-updated CDMs (for example 4.10.3112.0 under `~/.config/<app>/WidevineCdm/<version>/`); check **Diagnostics → CDM version**. If it still reports 4.10.2662.3, install or update a Chromium-based application that ships a newer ARM64 CDM, or point `QTWEBENGINE_CHROMIUM_FLAGS` at one. Codecs (AAC/MP3 verified) and the player UI are not involved.
- Native player buttons do nothing on the French page: fixed — controls now match fr + en labels ("Écouter", "Suivant", "Précédent", "aléatoire", "Répéter") plus data-testid hints, with carousel pagers ("Voir l'élément suivant/précédent…", "*PageButton") excluded; play/pause drives the page's media element directly, and `PlaybackRequiresUserGesture` is disabled so programmatic play() works.
- Playback errors after ~1s: the app passes `--widevine-cdm-path` automatically (check Diagnostics for the CDM in use). Run **Diagnostics → Test CDM session**: if session creation fails, the CDM is rejected by Chromium 140; if it succeeds (as observed), the failure is at license acquisition.
- The Amazon web player bar is never visible by design: the web view is docked so the page's bottom-docked player bar renders outside the visible window (`main_window._BrowserHost`). The page player is otherwise untouched — modifying its DOM/CSS correlated with playback teardowns. The native bottom bar drives it via clicks and mirrors its state via polling.
- Incompatible CDM: check ELF arch with file command.
- Login loops: clear site data via Settings menu.
- Audio failures: check PipeWire/PulseAudio.
- `ffmpeg not found` or unsupported-codec errors from `scripts/convert-to-mp3.sh`: on Fedora install the freeworld codec library from RPM Fusion free — `sudo dnf install ffmpeg libavcodec-freeworld` (stock Fedora uses `libavcodec-free`, which lacks some codecs).
- Renderer crashes: check logs in ~/.local/state/amazon-music-desktop/logs.
- Playback state questions: the app watches the page's media elements through a read-only event monitor (no page DOM changes); Diagnostics shows the normalized state (IDLE/LOADING/BUFFERING/PLAYING/PAUSED/STALLED/ERROR/ENDED), the last media event, and the playback pipeline stage statuses. STALLED means the position stopped advancing while the player claimed to be playing; ERROR means a media element reported an error.
- Desktop media controls (MPRIS) missing: the app registers `org.mpris.MediaPlayer2.amazon-music-desktop` on the session bus at startup. Without a session bus (or with `dbus-launch` unavailable) it stays unregistered. Controls are forwarded to the page player and status is mirrored from the monitor — a control has no effect if the page player is not running.
- Diagnostic report redaction: reports (Settings → Playback diagnostics → Copy diagnostic report) never contain cookies, authorization headers, tokens, account identifiers, or license traffic; URLs are stripped of query strings.
